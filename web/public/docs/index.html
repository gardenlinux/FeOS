FeRun and FeOS

FeOS is everything that runs on the nodes. It runs pods: Firecracker microVMs with containers in them that cost no memory while idle and are back in under a second. FeRun is the control plane above it, the Go program ferund in replicas over one PostgreSQL. It knows who owns each pod, where it runs and when it may sleep. FeCode builds its sandboxes, environments and builds on top of it.

Inside a node

On Kubernetes, FeOS runs as the DaemonSet feos-node: one pod per node, with the containers diskd and feosd. The microVMs live in feosd's container. A planned stop suspends them, and the next feosd resumes them (ADR 0020). Under systemd the same processes run without the pod around them.

A pod's network

  • An IPv6 address from the node's prefix: one the network routes to the node (--pod-prefix), or a /96 that ferund draws from the cluster's ULA /64 (--pod-network mesh). Plus an IPv4 /32 from 169.254.16.0/20, only for leaving the node through masquerade.
  • A routed TAP device per pod, pinned to its addresses and named by the pod's 11-character ID. Proxy ARP answers for the IPv4 gateway 169.254.0.1.
  • Security groups as nftables chains per pod and direction in the table inet feos. Rules only allow, without order; ferund sends them with a version per group.
  • DNS at 169.254.0.53 from feosd, with the environments' name tables. Metadata through Firecracker's MMDS v2.
  • Traffic records: flows from connection tracking, drops, DNS queries and server names, without eBPF and with nothing in the data path.

A request's path

A visitor opens a public environment's host under the apps zone, or a domain its tenant bound to it. ferund is not in the data path. It only supplies the table and wakes pods when asked.

CaaS on the sandbox engine

Environments are not a second system. Every pod of an environment is a row in the same table sandboxes as an agent's sandbox, and the same engine places, pauses and moves it (ADR 0018).

Inside ferund

One Go module (github.com/gardenlinux/feos/go), built static, with fixed dependencies: the standard library, pgx, gRPC, Protobuf, the MCP SDK, uuid, x/crypto, x/sync. The packages under go/internal/, grouped by what they do:

Front doors

api · auth · apierr · mcpsrv · ports · watch · ui

REST with its auth classes, OIDC sign-in, MCP for agents, the port door at /fwd/, file watches across instances, the embedded UI and this page.

Sandbox engine

sandbox · tools · podid

States, ops, placement (binpack or spread), sync and reconcile, tombstones, policies, images. Keyed tool calls outlive their caller (ADR 0023).

Environments

env · env/spec · env/addons · env/ctl · env/envdeps

Deployments with plan, base, revert and tags; the controller; addons on volumes; secrets; the route door; tenants' jobs.

Fleet

nodelink · fleet · mesh · pki · leader

The nodes' port with ALPN and stream budgets, joins, certificates, telemetry, events, each node's /96 and its peers, the CA with SPIFFE IDs, the leader lease.

Edge

ingress/service · ingress/table · routing · domains · acme

The API ferun-ingress calls and the table it routes from. Domains with a TXT proof and hourly checks, certificates over ACME.

Secrets

seal · bindings

AES-256-GCM under --secret-key-file for bindings and secrets. Kubernetes, SSH and HTTP bindings, the interception CA per pod, the HTTP preflight.

State

db · store · model · activity · config

PostgreSQL 17, READ COMMITTED with explicit row locks and retries, the embedded schema with its migrations, the partitioned activity log.

Tests and operations

testnode · e2e · server · kube · feosk8s

A Go implementation of the node's side for tests, end-to-end tests with several instances, the assembly of one instance, the feos-k8s controller.

Principles

  • Nodes open no port for control.They connect out to every instance of the control plane, with no broker in between.
  • No credential enters a pod.What a workload may use, feos-authn on the host adds or signs with.
  • Pods outlive their node agent.A restart or upgrade of feosd leaves the pods running, and the new feosd takes them over. On Kubernetes they are suspended and resumed for it.
  • A snapshot pins what it was written on.The Firecracker version, the CPU model and the host's kernel. Nodes keep the Firecracker versions their snapshots need.
  • PID 1 stays small.feos-host-init and feos-guest must not die; work that can fail runs in processes that can be restarted.
  • Static musl, syscalls first.No shared libraries, no shelling out to userspace tools. The one exception: mke2fs for new volumes in the guest.
  • The database's clock decides.Every lease, TTL and deadline in ferund uses PostgreSQL's now(). No node call inside a transaction.
  • FeOS knows pods.Whether a pod is an agent's sandbox or a customer's service, only FeRun knows.

Not built yet

Decided, but not built or only in part, per the ADR index and the architecture docs:

  • Images through the node (ADR 0022): the guest still pulls with the registry's token; feosd is to pull the layers and bake them into a sealed layer of diskd's.
  • Pod identity (ADR 0014): only feos-authn's HTTP side is built. The SPIFFE identity, FeID and the TLS, Kubernetes and SSH bindings are missing; the jail has no network namespace of its own yet.
  • Traffic records (ADR 0013) are made on the node but do not reach the control plane yet.
  • Environments: no volumes for services, no MCP tools and no CLI, no addon backups, no data on a clone.
  • Ingress: no DNS-01 wildcard, no L4, no h2c.
  • diskd: no sweep of old layers yet, no disk size per pod.
